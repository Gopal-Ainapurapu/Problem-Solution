Slide 01 • Executive Motivation

Problem Statement & Project Objectives

Civic Tech Innovation

⚠️ The Real-World Civic Crisis

  • • Frequent Public Hazards: Citizens endure open potholes, hazardous sewage leaks, uncleared garbage dumps, and dark street stretches causing injuries and health risks.
  • • The "Black Box" Portal: Traditional complaint systems leave citizens in the dark with zero visibility into whether complaints were received or acted upon.
  • • No Verifiable Audit Trail: Grievances are routinely closed arbitrarily on paper without physical site inspection or photographic proof.
  • • Blind Dispatch: Municipal authorities lack real-time visibility into volunteer locations, skills, active workloads, and exact coordinates.

🎯 LocalLens Solution Pillars

1. Citizen Empowerment & Transparency

Leaflet interactive click-to-pin map, HTML5 GPS auto-location, live 5-stage progress stepper, and one-click issue sharing.

2. Admin Command & Smart Geospatial Dispatch

Verification triage queue, proximity-based volunteer scanning, skill matching, Recharts visual analytics, and compliance CSV export.

3. Volunteer Hub & Private Team Workspaces

Available task discovery, assignment requests, team invitations, and dedicated private communication workspaces with real-time Socket.IO chat.

Slide 03 • System Design

Multi-Tier Architecture & End-to-End Data Flow

End-to-End Flow
Layer 1

Presentation Layer

React 19 SPA with role-based routes, Leaflet GPS coordinates, and Socket.IO client notifications.

Layer 2

Gateway & Security

Express 5 API server on port 5001. Rate limiting, CORS origin filters, and Bearer token validation.

Layer 3

Controllers & Sockets

Controllers for reports, teams, and users. Socket server orchestrating real-time user and private team rooms.

Layer 4

Persistence Layer

MongoDB Atlas with 2dsphere indexes. Aggregation pipelines for municipal analytics and audit logs.

Synchronous Event & Audit Pipeline

Every report state transition synchronously writes an immutable entry into statusHistory, logs the actor's ID and timestamp, creates a persistent Notification document in MongoDB, and dispatches an instant WebSocket push event to the user's active device room.

Slide 04 • Business Logic

Civic Issue Lifecycle & Role-Based Rules

Strict State Machine
Stage 1

PENDING

Citizen reports with GPS pin & photos

Stage 2

VERIFIED

Admin verifies; spam rejected with note

Stage 3

ASSIGNED

Single volunteer or team dispatched

Stage 4

IN PROGRESS

Arrival on site; work starts

Stage 5

RESOLVED

Notes & photo proof verified

🔒 Data Integrity Constraints

  • Sequential Permissibility: Cannot skip from Assigned to Resolved without first activating In Progress.
  • Role-Bound Operations: Volunteers can only update tasks assigned to them; unauthorized edits return HTTP 403 Forbidden.
  • Mandatory Resolution Notes: Resolution demands non-empty notes detailing physical actions taken.

🛡️ Terminal Rejection Protocol

Admins can transition Pending or Verified issues to Rejected with a mandatory justification (e.g. private gated layout outside municipal authority). Once resolved, reports cannot be rejected.

Immutable Audit Trail: Status changes cannot be altered or purged.

Slide 06 • Advanced Feature

Smart Nearby Team Formation & Private Group Collaboration

Socket.IO & 2dsphere

👥 Smart Recruitment & Capacity Rules

  • Configurable Team Size: Coordinators set requirements (e.g. 5 volunteers for culvert clearing).
  • Geospatial Proximity Scan: MongoDB calculates real-time distance in kilometers to available volunteers.
  • Targeted Invitations: Volunteers receive real-time push alerts and explicitly accept or decline.
  • Atomic Capacity Enforcement: The backend rejects any 6th member from joining a 5-member team.
  • No Duplicate Requests: Prevent duplicate requests and enforce account availability.

💬 Dedicated Private Team Workspace

  • Scoped Real-Time Chat: Socket.IO room team:REPORT_ID with JWT authentication on join.
  • Privacy Guarantee: Only confirmed members and coordinator can access messages. Unrelated users are rejected.
  • Coordination Checklist: Shared subtasks with checkbox toggling and completion percentages.
  • Dispatch Logistics: Physical meeting point, scheduled time, and coordinator notes.
  • Completion Evidence Review: Form for uploading resolution notes and photos; coordinator approves to resolve report.
